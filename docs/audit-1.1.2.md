# Повторный аудит 1.1.1 → 1.1.2

Повторная проверка выполнена другой моделью. Это **не слепой** аудит: история
предыдущей работы и отчёт 1.1.1 были доступны. Поэтому выводы 1.1.1 не принимались
на веру. Добавлены новые независимые методы, в первую очередь **выполнение на GPU**
со сравнением с точными моделями, а не только компиляция и `spirv-val`.

## Найденные и исправленные ошибки

| ID | Уровень | Ошибка | Исправление |
|---|---|---|---|
| G-1 | высокий | Унарный минус и `Abs` для целых выдавались через `OpSNegate`. Драйвер AMD (Radeon RX 9070 XT) оптимизирует его как операцию без знакового переполнения. На GPU `(-Low(Integer)) div 7` давал `+306783378` вместо `-306783378`, `(-A) < 0` — False, `Abs(A) >= 0` — True. Затрагивает и профиль Vulkan 1.0 (Integer), и Int64. По SPIR-V результат должен оборачиваться, но компилятор обязан давать определённую семантику на проверенном устройстве | Целое отрицание и `Abs` выдаются как `0 - X` (`OpISub`). Проверено, что этот путь драйвер не переписывает. Добавлены GPU-регрессия в `vulkan_smoke.py` (O0/O1) и SPIR-V-проверка отсутствия `OpSNegate` |
| C-1 | высокий | Выражение из нетипизированных констант сначала оборачивалось в 32 бита, потом **молча расширялось** в Int64/UInt64: `L := 100000 * 100000` → 1410065408, `L := 1 shl 40` → 256, `L := 2147483647 + 1` → -2147483648. Поведение появилось в 1.1 вместе с адаптацией деревьев констант | Точная проверка дерева (Int64 с контролем переполнения). Неявное преобразование обёрнутого дерева в другой целый тип — ошибка с подсказкой использовать типизированный операнд. Присваивание в тот же тип сохраняет модульную семантику 1.0. Обёрнутая нетипизированная `const` не становится адаптируемой |
| C-2 | средний | Несогласованность: `L := 100 * 1000` принималось, а `U := 4000000000 + 1` отклонялось. Литерал, приведённый внутри выражения, терял признак «нетипизированный» | Приведённый литерал остаётся адаптируемым; защиту даёт проверка точности C-1 |
| B-1 | низкий | Регрессия 1.1: имена модулей привязок `Byte`, `Word`, `Int64`, `UInt64`, `Double` стали запрещены (до 1.1 они были допустимы). Аудит 1.1.1 заменил в тесте `Byte` на `AnsiChar` вместо исправления | Скалярные типы в сгенерированном Delphi-модуле пишутся как `System.<Type>`. Прежние имена снова разрешены, тест восстановлен. Добавлена компиляция модулей Byte/Word/Int64/UInt64/Double настоящим Delphi с проверкой layout |

G-1 — дефект драйвера, но наблюдаемый результат был ошибкой компилятора: язык
обещает модульную арифметику (`Abs(Low(Integer)) = Low(Integer)`). Прежний
числовой аудит 1.0.x/1.1.1 этого не обнаружил, потому что не комбинировал
отрицание минимального значения с последующим делением или сравнением.

## Новые проверки

Все GPU-проверки — Python stdlib, Vulkan 1.2, настоящий dispatch на устройстве:

- `tests/audit_typed_trees.py` — случайные деревья по Byte/Word/Integer/Cardinal/
  Int64/UInt64/Single/Double: `+ - * div mod and or xor shl shr not`, отрицание,
  приведения, Min/Max/Abs/Clamp. Каждое дерево вычисляется четырьмя способами:
  типизированная `const` (хост ConstEval), литералы в Main при O0 (GPU/драйвер)
  и O1 (свёртка хостом), листья из буфера (только GPU). Всё сравнивается с точной
  моделью на Python (целые и `Fraction` с округлением до ближайшего чётного).
  Деление, `Sqrt` и переполнение float исключены: они не заявлены как точные.
- `tests/audit_flow_runtime.py` — случайные программы: `for/while/repeat`,
  `Break/Continue`, `case`, `Exit` из Main, `var`-алиасы (`Mix(X, X)`), функция
  с `Exit(Value)`. Трасса каждого из 64 потоков сравнивается с независимым
  интерпретатором на Python.
- Проверка соответствия `required_features` в reflection реально выданным
  capabilities и execution modes. Расхождений не найдено.
- Точечные проверки на GPU: вложенные таблицы констант (Int64, Byte, Double),
  индексы Byte/Word/Int64, процедуры с доступом к push constants и буферам,
  case по Int64 с граничными метками, циклы Byte 0..255, `Round` в условиях
  `while/repeat`.

## Результаты (Delphi 13 Win64, AMD Radeon RX 9070 XT)

- `scripts/test.ps1`: **1163** проверки, Vulkan 1.0/1.2 SPIR-V validation.
- Деревья типов: **87 600** сравнений после исправлений (seeds 930200, 931000,
  932000, 933000, 934000; глубина до 6), O0/O1, совпадение 100%.
- Выполнение управляющих конструкций: **260** программ × 64 потока × O0/O1,
  **1 597 440** значений трассы (seeds 940311, 940500, 941000, 942000).
- Финальный прогон частично с Khronos validation layer. Повторно прошли: `vulkan_smoke.py` (52 dispatch), `vulkan_extended.py`,
  `audit_numeric_gpu.py`, `audit_extended_gpu.py` (286 720 результатов),
  `audit_flow.py` (1000 программ, seed 811039).

## Подтверждено без изменений

- Нативное Double-деление по-прежнему не побитово точное (до 1 ULP; в пределах
  точности Vulkan). Для побитово точного результата нужна программная реализация. Компилятор её
  не подменяет.
- Ограничения дизайна, а не ошибки: `1 shl 40` в контексте Integer маскирует
  счётчик (как 32-битная арифметика 1.0); `Round/Trunc` возвращают Int64 и
  поэтому требуют Vulkan12; float→integer cast вне диапазона не определён.

## Ограничения аудита

Конечное число seeds и одно устройство/драйвер. Это не доказательство корректности
всех программ и не квалификация других GPU. Найденный G-1 показывает, что
поведение драйвера надо проверять выполнением; на другом устройстве нужен
повторный прогон GPU-проверок.
