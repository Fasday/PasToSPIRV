# SoftDouble — точное деление Double

`lib/SoftDouble.pasm` — модуль на языке PasToSPIRV (не часть компилятора) для деления
binary64 с правильным округлением. Встроенное деление `Double` на GPU по спецификации
Vulkan не обязано быть правильно округлённым (допуск 2,5 ULP); `[StrictFloat]` это не
меняет. На проверенном AMD-устройстве встроенное деление отличалось от правильного на
1 ULP примерно в четверти случаев (см. [audit-1.1.1.md](audit-1.1.1.md)).

```pascal
uses SoftDouble;

var
  [Binding(0, 0)] Data: array of Double;

[Vulkan12]
procedure Main;
begin
  Data[GlobalInvocationID.X] := SoftDiv(1.0d, Data[GlobalInvocationID.X]);
end;
```

```powershell
.\build\bin\PasToSPIRV.exe compile shader.pas -I lib -o shader.spv
```

## API

| Функция | Описание |
|---|---|
| `SoftDiv(A, B: Double): Double` | `A / B` |
| `SoftDivBits(A, B: UInt64): UInt64` | То же для битовых образов binary64; не использует тип `Double` |

## Контракт

Результат **побитово совпадает** с SSE2 `DIVSD` на x86-64 (Delphi Win64) при MXCSR по
умолчанию: округление к ближайшему чётному, без FTZ/DAZ, исключения замаскированы.

- Субнормальные операнды и результаты обрабатываются полностью, включая округление
  результата в наименьшее нормальное число.
- Переполнение даёт `±Inf`, деление конечного числа на `±0` — `±Inf`, конечного на `±Inf` — `±0`.
- NaN по правилам `DIVSD`: NaN делимого имеет приоритет над NaN делителя и возвращается
  с установленным битом quiet (payload сохраняется); `0/0` и `Inf/Inf` дают
  `$FFF8000000000000` (x86 «real indefinite», знак минус).
- Только режим округления к ближайшему чётному. Флаги исключений не вычисляются.
- Вычисления целочисленные (`UInt64`, `Cardinal`), поэтому результат не зависит от
  режимов float на устройстве. `Single` используется только для оценки цифры частного,
  ошибка оценки исправляется точной проверкой остатка.
- Профиль: `[Vulkan12]` на `Main`; reflection требует `shaderInt64`, при использовании
  `SoftDiv` также `shaderFloat64`. Копирование значений `Double` (параметры, буферы)
  не меняет биты; если NaN-payload важен и тракт данных неизвестен, используйте
  `SoftDivBits` с `DoubleToBits`/`BitsToDouble` на границах.

## Алгоритм

1. Особые случаи (NaN, бесконечности, нули) в порядке правил `DIVSD`.
2. Мантиссы с неявной единицей приводятся к `[2^52, 2^53)`, субнормальные операнды
   нормализуются через `FindMSB`.
3. Частное `floor(MA * 2^53 / MB)` (54 бита: мантисса и бит округления) строится цифрами
   по 9 бит. Оценка цифры — через `Single`-обратную величину, затем коррекция по
   точному остатку `R < MB < 2^53`; все промежуточные значения меньше `2^63`.
4. Округление к ближайшему чётному по биту округления и «липкому» биту (остаток не ноль);
   для субнормального результата выбывающие биты добавляются в «липкий» бит.

## Проверка

```powershell
.\scripts\test.ps1 -SkipBuild            # компиляция модуля, профиль, reflection
python .\tests\softdouble_gpu.py         # GPU против Delphi DIVSD
python .\tests\softdouble_gpu.py --count 1000000 --seed 11
```

`softdouble_gpu.py` сравнивает `SoftDivBits` и `SoftDiv` (O0 и O1) с делением, выполненным
программой `tests/SoftDoubleCheck.dpr` (собирается в `test.ps1`), включая NaN-payload, нули,
бесконечности, субнормальные значения, точные «ничьи» субнормального округления и границы
переполнения. Часть конечных результатов дополнительно сверяется с независимым оракулом
на `fractions.Fraction`. Проверялось на AMD RX 9070 XT: 2 × 10^6 случайных и граничных пар
без расхождений. Это проверка на конкретном устройстве, не доказательство для всех GPU.

По грубому замеру на том же устройстве `SoftDivBits` работает примерно со скоростью
встроенного деления `Double` и в 1,3–1,8 раза быстрее побитового деления в столбик.
Результаты замера зависят от устройства и окружения.
