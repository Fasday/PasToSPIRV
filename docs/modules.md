# Исходники, модули и общий CPU/GPU-код — 1.x

Есть два независимых механизма:

- **`uses Name;`** — загрузка declaration-модуля `Name.pasm` ровно один раз;
- **`{$I 'file.inc'}` / `{$INCLUDE 'file.inc'}`** — текстовая вставка, включая повторные вставки.

Это не полноценные Delphi units и не произвольный Pascal-препроцессор.

## Модули `.pasm`

```pascal
module ScalarMath;
uses BitMath;

function Transform(Value: Cardinal): Cardinal;
begin
  Result := MixBits(Value, 3);
end;
```

В shader entry file импорт располагается перед `type`, ресурсами и функциями:

```pascal
uses ScalarMath;

procedure Main;
begin
  // Здесь доступны Transform и объявления транзитивных зависимостей.
end;
```

Правила:

- Имена модулей не могут совпадать с зарезервированными словами, встроенными типами,
  built-ins (`GlobalInvocationID` и др.) или intrinsics: иначе `Name.X` мог бы
  подменить встроенное значение.
- Один `uses` на заголовок, имена через запятую; имя простое, без namespace-точек
  и строковых файловых путей. Имена модулей сравниваются без учёта регистра.
- Ищется `Name.pasm`, его `module Name;` должен совпадать с импортом.
- Модуль содержит `const`/`type` блоки, функции и процедуры. Ресурсы, глобальные переменные,
  `Main`, initialization/finalization, `interface`/`implementation` не поддерживаются.
- Зависимости компилируются до зависимых модулей; diamond/repeated imports не
  создают повторных определений. Циклы модулей отклоняются с цепочкой имён.
- Типы/функции/константы доступны как `ScalarMath.Transform(...)`, `Types.TItem`,
  `Config.BlockSize`. Неквалифицированное имя допустимо, если однозначно.
  Private/export-секций пока нет.
- Экспортируемые имена уникальны **внутри модуля**. При совпадении имён разных
  импортов нужен qualifier. Own declaration имеет приоритет. Перегрузки (`overload`)
  объединяются только внутри одного модуля.
- Модуль видит свои объявления и транзитивные зависимости своего `uses`.
  Нельзя случайно воспользоваться объявлением другого модуля лишь потому,
  что shader импортировал его раньше: потребуется добавить зависимость.
- Локальные имена не затеняют видимые объявления. Объявления несвязанных модулей
  не меняют разрешение локальных параметров. Shader видит все загруженные зависимости.
- Внутри одного модуля сохраняется порядок объявления функций/типов до использования;
  `forward` позволяет объявить функцию раньше её определения в том же модуле.
  Рекурсия запрещена. Перечисления модуля доступны как `Module.Value` и `Module.TEnum.Value`.

## Текстовые include

```pascal
{$I 'shared/Types.inc'}
{$INCLUDE 'shared/Math.inc'}
```

Допустима и форма `(*$I 'file.inc'*)`. Путь может быть без кавычек, если не
содержит пробелов. Поддерживаются одинарные/двойные кавычки и удвоенная кавычка
внутри имени. Файлы читаются как строгий UTF-8, BOM допустим.

**На строке — только пробелы/табуляции и директива.** Inline include и хвостовой
комментарий отклоняются. Это позволяет сохранить однозначное соответствие
файл/строка/столбец. Директивы внутри комментариев не выполняются.

Include можно ставить на месте допустимого фрагмента: перед типами/функциями,
внутри тела, в модульной обёртке. Он не сортирует объявления и не добавляет область
видимости. Повторный include повторяет код; при дублировании функций/типов будет
обычная ошибка повторного определения. Комментарии должны закрываться в своём файле.

Кроме include, поддержаны только `{$B+/-}` и `{$BOOLEVAL ON/OFF}` (полное или
сокращённое вычисление `and/or`, см. [language.md](language.md#логические-значения)).
Состояние проходит через include, а каждый модуль начинается с `{$B-}`.
Другие директивы (`$IFDEF`, `$DEFINE`, `$Q`, `$R` и т. п.) запрещены.
`{$I+}`/`{$I-}` не считаются именами файлов: настройка Delphi I/O checking
не поддерживается. Нет макросов, include guards и условных CPU/GPU-ветвей.

## Поиск файлов

```powershell
.\build\bin\PasToSPIRV.exe compile .\examples\modules_compute.pas -I .\examples\modules -o .\build\modules.spv
```

`-I <directory>` и `--include <directory>` — эквивалентны, можно повторять.
Явные относительные `-I` разрешаются от рабочего каталога процесса.

Для каждой зависимости проверяются:

1. каталог **физического файла, содержащего ссылку**, в том числе вложенного `.inc`;
2. все явно переданные каталоги `-I`.

Если найдено несколько разных нормализованных путей — ошибка неоднозначности,
а не молчаливый выбор первого. Повтор одного каталога не создаёт неоднозначность.
Текущий рабочий каталог, `PATH` и пути Delphi не являются неявным поиском.
Это правило применяется и к относительным include-путям с подкаталогами.

Абсолютные include-пути не принимаются: внешние каталоги передаются через `-I`.
Относительный `..` допустим, поэтому file API **не является filesystem sandbox**.
Для недоверенных проектов нужна внешняя изоляция/политика доступа либо string API.
Символические ссылки не канонизируются по файловому ID; поиск использует
нормализованные полные пути и ограничения глубины.

## API и диагностика

```pascal
// Без файлового I/O: самостоятельный shader-фрагмент.
Result := TShaderCompiler.Compile(Source);

// Чтение entry file, модулей и include; результаты остаются в памяти.
Result := TShaderCompiler.CompileFile(
  ShaderFile, TArray<string>.Create(ModuleDirectory), 'ModuleBindings');
```

String API не разрешает файловые зависимости: `uses`/include требуют `CompileFile`.
File API не записывает `.spv`/JSON/unit; запись выполняет CLI или вызывающее приложение.

`EShaderError.Position.FileName`, `Line`, `Column` указывают на исходный физический
файл, в том числе `.inc`, а не на номер строки в развёрнутой склейке.
Заголовки маскируются пробелами, include имеет карту исходных строк.
CLI сохраняет эти координаты; перенаправленные stdout/stderr используют UTF-8,
не меняя настройки интерактивной консоли.

В рамках одной компиляции каждый физический нормализованный путь читается один
раз; повторные вставки используют его содержимое из памяти. Это не persistent
incremental cache и не атомарный snapshot всего файлового дерева.

Ограничения file frontend:

- до 512 файлов и 8 MiB суммарного сырого UTF-8;
- до 65536 рёбер графа зависимостей; ребро include записывается один раз на
  директиву, даже если файл с ней включён многократно (развёртка кешируется);
- строки считаются физическими: завершающий перевод строки не открывает новую строку;
- до 64 уровней файлов include (включая корневой документ) и 64 модулей в цепочке зависимостей;
- до 4096 элементов `uses` в заголовке;
- до 8 * 1024 * 1024 UTF-16 символов и 200000 строк развёрнутой программы;
  отдельный бюджет 200000 строк применяется к исходным файлам.

Ошибки поиска, циклов, синтаксиса и бюджетов — source error, CLI code 1.
Недопустимые символы в имени include (`<`, `|`, `*` и т. п.) — тоже source error с
позицией директивы. Существующую, но нечитаемую зависимость CLI сообщает как
source error (code 1) с позицией ссылки. Некорректный `-I`/I/O entry file — code 2. При ошибке исходника существующие
SPIR-V, JSON и bindings не изменяются.

## Граф зависимостей в JSON

Схема ABI остаётся **v2**, добавлены поля file mode:

- `sources`: `{id, path, sha256}` — hash **сырых байтов**, включая BOM/переводы строк;
- `modules`: `{name, file_id}` в порядке компиляции зависимостей;
- `source_dependencies`: `{from, to, kind, line, column}`, kind=`include`/`uses`.

`from/to/file_id` ссылаются на `sources[].id`. Это входы для внешней системы сборки,
а не встроенный механизм кеширования.

Пути записываются относительно entry directory с `/`. Для другого диска могут
использоваться `@I<N>/...` или `@external/<hash-prefix>/<filename>`; абсолютные
рабочие пути не попадают в артефакты. В диагностике остаётся полный локальный путь.
Сам SPIR-V не содержит filesystem provenance. Изменение строк/путей не должно
считаться изменением ABI; hash описывает конкретный прочитанный источник.

## Реально общий CPU/GPU-исходник

Пример разделён на:

- `examples/shared/Params.inc`, `Bits.inc`, `Math.inc` — точные общие файлы;
- `examples/modules/*.pasm` — shader-обёртки с `module/uses/include`;
- `examples/modules_compute.pas` — compute entry point;
- `tests/SharedSourceCheck.dpr` — Delphi CPU reference, включающий **те же** `.inc`.

`.pasm` не компилируется Delphi как unit. Совместим именно выбранный общий
Pascal-фрагмент: здесь скалярные операции и простая POD-запись. GPU-векторы и
intrinsics не становятся автоматически операторами/функциями Delphi RTL.

CPU wrapper задаёт `$Q-/$R-`, использует явные 32-битные типы/преобразования;
настройки не прячутся внутрь общего файла. На GPU семантика остаётся фиксированной.
Для `Single` всё равно существенны округление, FMA, денормализованные значения,
NaN и режим CPU-исключений. Само совпадение текста не доказывает эквивалентность.

```powershell
.\scripts\test.ps1
python .\tests\vulkan_smoke.py --require-shared-cpu
```

Первый шаг собирает CPU reference. Второй сравнивает Delphi и GPU для нескольких
чисел итераций: целые — побитово, выбранные конечные `Single` — с допуском `1e-6`,
проверяет хвосты и `Count=0`. Он требует свежий CPU executable после изменения `.inc`.
Без `--require-shared-cpu` отсутствие/устаревание reference помечается предупреждением,
а именно это сравнение пропускается; остальные Vulkan-проверки продолжаются.
